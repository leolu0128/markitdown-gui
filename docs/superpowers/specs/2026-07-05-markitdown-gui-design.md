# MarkitDown GUI 批次轉換工具 — 設計文件

日期：2026-07-05
狀態：已由使用者核准

## 目標

在 `D:\MarkitDown` 建立一個 Tkinter 圖形介面工具，讓使用者能：

1. 一次選擇多個來源檔案（PDF、Word、PowerPoint、Excel、圖片、HTML、CSV 等 markitdown 支援的格式）
2. 選擇 Markdown 檔案的輸出資料夾
3. 批次轉換，輸出檔名沿用來源檔的主檔名（`報告.docx` → `報告.md`）

## 技術選型（已與使用者確認）

- **GUI 框架**：Tkinter（Python 內建，免額外 GUI 依賴）
- **轉換核心**：`markitdown[all]`（全格式支援），安裝進現有 `.venv`（Python 3.13.8）
- **同名檔處理**：直接覆寫
- **啟動方式**：雙擊 `.bat` 啟動檔（使用 `pythonw.exe`，不顯示命令列視窗）

## 專案結構

```
D:\MarkitDown\
├── .venv\                    # 既有虛擬環境
├── gui.py                    # 主程式（GUI + 轉換邏輯）
├── MarkitDown轉換器.bat       # 雙擊啟動檔
└── docs\superpowers\specs\   # 設計文件
```

## 架構

單檔 `gui.py`，內部分為兩層：

- **轉換層**：`convert_one(src_path, out_dir) -> (ok, message)`。以模組層級單例建立 `MarkitDown()` 實例，輸出檔名為 `Path(src).stem + ".md"`，以 UTF-8 寫入，同名直接覆寫。所有例外在此層捕捉並回傳錯誤訊息，不外洩。
- **UI 層**：Tkinter 主視窗。按下「開始轉換」後在 `threading.Thread` 背景執行緒逐一轉檔，透過 `queue.Queue` + `root.after()` 輪詢把進度回傳主執行緒更新畫面（Tkinter 只能在主執行緒操作 UI）。

## 介面配置（單一視窗）

1. **檔案清單區**（Treeview，兩欄：檔名、狀態）
   - 「加入檔案」：多選檔案對話框，可重複加入（重複路徑自動去除）
   - 「移除選取」、「清空清單」
2. **輸出資料夾**：文字欄 + 「瀏覽」按鈕；預設為第一個加入檔案所在的資料夾
3. **開始轉換**：轉換期間停用（避免重複觸發），清單狀態即時更新：等待中 → 轉換中 → ✅ 完成 / ❌ 失敗（含簡短錯誤訊息）
4. **底部**：進度條（determinate，依完成檔數推進）+ 狀態文字（如「3/10 完成」）
5. **完成時**：訊息框顯示成功／失敗統計，提供「開啟輸出資料夾」

## 錯誤處理

- 不支援的格式、檔案被佔用、markitdown 內部例外 → 標記該檔為失敗並附訊息，不中斷整批
- 未選檔案或未選輸出資料夾就按開始 → 提示訊息框
- 輸出資料夾不存在 → 自動建立

## 測試

- 轉換層以 pytest 測試：輸出檔名規則（主檔名沿用、副檔名 .md）、覆寫行為、失敗回報（不支援格式）
- UI 層以手動煙霧測試驗證（啟動、選檔、轉換、狀態顯示）
